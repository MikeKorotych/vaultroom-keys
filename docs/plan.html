Vaultroom
Keys.

Зашифрованный backup для API-ключей и developer secrets. Сервер синхронизирует ciphertext, но не получает мастер-пароль, ключ расшифровки или содержимое vault.

Current phasePRIVATE BETA · LIVE

Core flow проверен на production. Для критичных ключей пока нужен независимый encrypted backup.

Problem

API-ключи лежат локально без нормального backup.

Первый релиз решает одну личную задачу: сохранить токены и recovery codes так, чтобы потеря Mac не уничтожила их, а взлом базы не раскрыл значения.

The web caveat

Если сервер может заменить JavaScript, он может украсть plaintext после unlock. Поэтому vault route не должен загружать analytics и third-party scripts. Нужны CSP, Trusted Types, pinned dependencies и release hashes. Долгосрочно подписанный desktop client даёт более сильную code-integrity boundary.

Irreversible loss

Нет server-side reset. Если потеряны passphrase и recovery key, vault восстановить невозможно. UI должен говорить об этом до первой записи.

Format v1

Whole-vault encrypted payload. Server sees blob size, revision and timestamps, but not item count, labels, services or values.

Local state

IndexedDB stores ciphertext. Plaintext lives in memory only while unlocked. Export uses the same versioned encrypted envelope.

Sync

Optimistic revision check. Stale writes fail with a conflict. Server retains a bounded history of encrypted blobs.

Recovery

A high-entropy recovery key creates a second wrapper for the same vault data key. It is shown once and never uploaded in plaintext.

Module boundary

packages/crypto imports no React, Clerk or network code. It exposes versioned encrypt, decrypt, wrap and unwrap functions.

Tests

Wrong passphrase, tampering, recovery, export/import, clean-browser restore and plaintext-marker inspection pass. Golden vectors and broader browser coverage remain.
